# 产品与技术方案


## 第三章  产品与服务

本章回答“我们到底卖什么”。撰写商业计划书的“产品与服务”一章时，按“产品定位与形态 → 系统组成 → 功能清单 → 使用流程 → 产品边界”的顺序组织。其中**产品边界**（4.5 节，即“我们不做什么”）极易被忽略，但它是答辩中最能体现团队成熟度的一节，务必保留。


### 3.1 产品定位与形态

安步是一套**面向老龄人群的无穿戴步态量化与跌倒风险预测系统**。它的定位可以概括为三句话：

- **对老人，它是一个不存在的东西。**没有手环、没有贴片、没有需要充电的设备、没有需要每天配合完成的动作。老人唯一要做的就是像平时一样在走廊里走路。

- **对机构，它是一份可以放进护理流程的连续数据。**把“谁需要重点看护”从经验判断变成看板上的风险排序，把有限的护理人力投向最需要的人；同时留下带时间戳的客观记录。

- **对家庭，它是一个不用学就会用的安心感。**家属在手机上看到的是“本周步速略有下降，建议关注”这样的趋势提示，而不是一堆专业参数。

产品由四个部分构成，其中前两部分是核心交付物，后两部分是配套：

| 组成部分 | 形态 | 作用 | 交付方式 |
|---|---|---|---|
| 安步边缘计算盒 | 硬件：RK3576 核心板 + 底板 + 外壳 + 电源，配 USB 摄像头（UVC 免驱） | 在设备内完成视频采集、姿态估计、步态计算与风险推理，视频不出设备 | 整机销售或租赁 |
| 端侧算法与固件 | 软件：RKNN 量化模型 + 步态与风险算法 + 设备管理与本地告警 | 核心壁垒所在。含改进姿态估计模型、步态参数提取模块、风险分层模型 | 随硬件交付，按设备授权 |
| 机构管理后台 | 软件：Web 看板 + 风险趋势 + 干预建议 + 护理任务派发 | 面向院长与护理主管；风险排序、趋势曲线、干预建议与干预记录 | 按床位订阅 |
| 家属端小程序 | 软件：微信小程序或轻应用 | 面向子女；风险等级、趋势摘要、跌倒事件通知与照护建议 | 随订阅包含 |


### 3.2 硬件配置与成本结构

硬件选型遵循一条原则：**用得起、装得上、修得快。**养老机构与家庭不是实验室，任何需要专业安装、需要特殊网络、需要定期维护的方案都活不下来。因此本项目刻意选择了最普通、最容易获得的硬件组合。

| 部件 | 本项目选型 | 选择理由 | 可替代性 |
|---|---|---|---|
| 主控芯片 | 瑞芯微 RK3576（8nm，4×A72 + 4×A53，NPU 6 TOPS INT8，Mali-G52 MC3） | 端侧算力足够跑实时姿态估计；配套 RKNN-Toolkit2 工具链成熟；国产芯片供应与生态支持稳定；支持 LPDDR5 与 USB 3.0 | 可平滑迁移至同系列更高算力型号，算法侧只需重新量化 |
| 摄像头 | USB 摄像头（UVC 免驱），200 万像素级，固定机位，含可选广角镜头 | 免驱免开发，即插即用；价格低廉；机构与家庭可自行更换、可随时采购备件 | 高。任意 UVC 摄像头均可，也可换用 MIPI CSI 摄像头进一步提升画质 |
| 安装方式 | 墙面或立杆固定，高度约 2.0–2.4 米，俯角向下对准走廊直线行走路径 | 覆盖 3–5 米行走段即可提取完整步态周期；避免拍摄到床、卫生间内部等敏感区域 | 不适用（属部署规范） |
| 整机成本 | 【待实测：样机 BOM 成本】 | 以团队实际采购清单为准，逐项列出核心板、底板、摄像头、外壳、电源、线材的采购价与采购日期 | ★★ 必须自测，这是财务模型与定价论证的基石 |
| 对比：临床设备 | 三维动作捕捉系统 / 电子步道，数十万元级 | 作为成本对比的锚点，用于说明本项目的成本优势 | ★ 必须完成询价并记录渠道与日期 |

说明：上表中“整机成本”与“临床设备价格”两行是本节的关键。本项目相对临床方案的成本优势，是整个商业模式的支点，因此这两个数字必须是真实调研与实测的结果，不得使用估计值或二手转述。


### 3.3 核心功能清单

把系统能力拆成可演示、可验收的功能点，是写商业计划书和做 PPT 时最有用的素材。下表按“基础—核心—增值”三层组织，也对应了商业模式中的三层收入结构。

| 层级 | 功能 | 说明 | 验收方式 |
|---|---|---|---|
| 基础 | 自然行走步态采集 | 老人在摄像头视野内自然行走 3–5 米即可完成一次采集，无需穿戴、无需配合、无需专人引导 | 现场演示：老人走过 → 系统自动输出本次数据 |
| 基础 | 多目标识别与身份保持 | 支持同一场景内多名老人，通过衣着与体态特征做身份关联，避免数据串行 | 现场演示：两人同框，数据分别归入各自档案 |
| 核心 | 步态参数自动计算 | 输出步速、步长、步频、步幅时间变异系数（CV）、双支撑相占比、对称性等参数 | 与本文档 4.3 节的参数表逐项对照；打印单次报告 |
| 核心 | 跌倒风险分层与评分 | 输出低、中、高三档风险等级与连续风险评分，并给出主要贡献因素（可解释性） | 风险看板演示；SHAP 贡献度图示 |
| 核心 | 趋势追踪与恶化预警 | 同一老人多日数据形成趋势曲线；当风险评分或关键参数出现显著恶化时主动提示 | 展示一位模拟用户 30 天的趋势曲线 |
| 核心 | 跌倒事件检测（事后兜底） | 在预测之外，提供跌倒事件的实时检测与告警，作为安全兜底能力 | 现场演示：模拟跌倒 → 告警触发 |
| 增值 | 干预建议生成 | 根据主要风险贡献因素，输出对应的可执行建议（肌力训练、用药复核提示、环境改造、护理频次调整） | 报告样例；建议与参数的对应关系表 |
| 增值 | 护理任务派发与记录闭环 | 把高风险老人自动转为护理任务，记录干预执行情况，形成“识别—干预—复评”闭环 | 后台操作演示 |
| 增值 | 机构风险看板与报表 | 按楼层、护理等级、时间维度聚合风险分布，支持导出用于例会和纠纷说明 | 导出报表演示 |
| 增值 | 结构化数据接口 | 只输出结构化指标（不含视频），可对接机构现有护理系统或区域养老平台 | 接口文档 + 一次真实调用 |


### 3.4 三步使用流程

产品的使用流程必须简单到可以让护理员在培训半小时后独立操作。因此本项目刻意把流程压缩为三步：

- **第一步：装。**把边缘盒接上电源与摄像头，摄像头按部署规范固定在走廊一侧的墙面或立杆上，高度约 2.0–2.4 米，俯角对准直线行走路径。边缘盒接入机构现有网络（Wi-Fi 或有线），开机自动联网与自动注册，无需配置服务器地址。

- **第二步：走。**在系统中为老人建立档案并完成一次“注册行走”（用于身份关联与个体基线标定，同时录入身高，用于单目尺度标定）。此后老人每日自然经过即可，无需任何配合动作。**这一步是本项目与传统方案最大的区别：数据采集不再是需要组织的一项工作，而是融入了日常生活。**

- **第三步：看。**护理人员在后台看到风险排序与趋势曲线，按提示对高风险老人执行干预并记录；家属在小程序上看到趋势摘要与异常通知；系统按日、周、月自动生成风险报表。

为了让流程在 PPT 上更直观，可以把它画成一条横向流程链：

```
固定安装  →  一次注册行走（建档 + 录入身高）  →  每日自然通行
     ↓
端侧推理（关键点 → 步态参数 → 风险评分）  →  看板排序与预警
     ↓
干预执行与记录  →  复评  →  趋势更新（形成闭环）
```


### 3.5 产品边界：我们不做什么

明确说清“不做什么”，是让评委相信团队想清楚了的一种方式。本项目的边界有四条，每条都有明确的理由。

| 不做什么 | 理由 | 如果做了会怎样 |
|---|---|---|
| 不做跌倒防护的物理干预设备<br>（不生产扶手、地垫、防摔服、髋部保护器） | 这些是成熟品类，有成熟的供应链与品牌，我们的价值在“识别谁需要防护”，不在“生产防护品” | 会分散研发与资金，进入一个自己不占优势的低毛利制造领域 |
| 不做医疗器械的诊断结论<br>（不输出疾病诊断、不替代医生判断） | 本项目的定位是健康管理与风险筛查，输出的是“风险提示”而非“诊断结论”，这在合规上更可控，也更符合落地场景的实际需求 | 会立即触及医疗器械注册与临床责任问题，在项目早期是无法承受的合规负担 |
| 不做穿戴式设备<br>（不出手环、贴片、鞋垫传感器） | 穿戴设备的根本问题是依从性：老人忘记佩戴、忘记充电、抗拒佩戴，而这恰恰是本项目要解决的问题 | 会重新引入依从性问题，把“无感监测”变成“又一件需要老人配合的事” |
| 不做通用人体行为分析平台<br>（不做员工管理、客流统计等泛化能力） | 注意力是学生团队最稀缺的资源，聚焦在“步态与跌倒风险”这一个垂直场景，才有可能做出真正的精度优势 | 会变成“什么都能做、什么都不精”的通用视觉平台，在答辩中反而难以说清价值 |


### 3.6 交付物样例：一次评估输出什么

为了让评委直观理解产品的价值，答辩现场最好能展示一份真实的评估输出。下表是一份标准输出的结构，制作 PPT 时可直接据此设计页面。

| 输出模块 | 内容 | 面向谁 | 作用 |
|---|---|---|---|
| 风险总览 | 风险等级（低/中/高）+ 风险评分 + 较上周变化箭头 | 护理主管、家属 | 一眼看到结论，不需要理解参数 |
| 关键参数卡 | 步速、步频、步长、步幅时间变异系数等，每项给出数值、参考区间与趋势箭头 | 护理主管、康复医师 | 支撑专业判断，也是与临床沟通的语言 |
| 主要贡献因素 | 按贡献度排序的风险因素（如步速下降、变异系数升高、双支撑相延长） | 康复医师、护理主管 | 回答“为什么风险是高的”，这是可解释性的体现 |
| 趋势曲线 | 近 30 天风险评分与关键参数的变化曲线 | 所有人 | 把“单次快照”变成“连续过程”，这是本项目最核心的价值可视化 |
| 干预建议 | 与主要贡献因素一一对应的可执行建议 | 护理主管、家属 | 把识别转化为行动，避免“知道了也没用” |
| 质量声明 | 本次采集的有效步数、置信度、是否达到有效评估条件 | 护理主管、康复医师 | 诚实标注数据质量，避免用低质量数据做高风险判定 |

“质量声明”这一行值得特别说明：本系统在有效步数不足、遮挡严重、光照异常时会明确标注“本次数据置信度低，未参与风险判定”，而不是硬给一个评分。这是与许多演示型系统的重要区别，也是答辩中被追问“数据不准怎么办”时的标准答案。

## 第四章  技术方案与核心竞争力

本章是全文档技术部分的核心。撰写商业计划书时，技术章节容易写成“技术堆栈清单”，那是失败写法。正确的写法是先讲清**问题结构**（我们面对的是一个什么形状的问题），再讲**核心构造**（我们用什么方法回应），最后才讲架构与选型。

阅读建议：4.1 节是本章的骨架，务必先读懂“四级映射”与“四个缺口”，后面四节是对四个缺口的逐一回应；4.6 节的五层架构用于画图；4.9 节的诚实声明用于答辩防守。


### 4.1 问题定义：从像素到风险的四级映射与四个缺口

本项目的技术链路可以抽象为一条四级映射。每往下一级，都会丢失一部分信息，并引入一类新的误差。把这条链路画出来，问题就变得清晰了：

```
第一级   视频帧  →  人体关键点
           缺口①：通用关键点协议为“关节定位”优化，不是为“步态测量”优化；
                  踝、足关键点误差直接放大为步长与足廓清误差

第二级   人体关键点  →  步态参数（物理量）
           缺口②：像素坐标不是物理尺度，单目相机没有深度信息；
                  步长、步速这些“多少厘米、多少米每秒”需要尺度标定

第三级   步态参数  →  风险评分
           缺口③：单次参数是快照，而风险是随时间演化的过程；
                  且单一指标判别力有限，需要多参数融合与趋势建模

第四级   风险评分  →  落地部署
           缺口④：模型算力需求与边缘设备算力之间的矛盾；
                  以及视频上云带来的隐私合规与网络依赖问题
```

这条链路的意义在于：**它把“做一个跌倒风险预测系统”这个模糊的目标，分解成了四个边界清晰的技术问题。**每一个缺口对应本项目一条创新点，也对应一个可以单独做实验、单独出数据的子课题。答辩时按这条链讲，评委能立刻理解你们的技术思路是成体系的，而不是几个模块的简单拼装。

| 缺口 | 问题的本质 | 本项目的回应 | 对应章节 |
|---|---|---|---|
| 缺口①<br>关键点协议不匹配 | 通用姿态模型的评价指标是关节位置平均精度，而步态测量真正需要的是踝、足、骨盆在下肢运动中的稳定相对定位；误差来源不同，优化目标也不同 | 扩展下肢关键点协议（增加足尖、足跟、骨盆点），改进关键点回归方式以降低量化误差，引入时序跟踪保证足端轨迹连续 | 4.2 节<br>创新点一 |
| 缺口②<br>像素不是物理量 | 单目视觉存在尺度不确定性：同一姿态在不同距离下投影为不同大小的像素图案，因此无法直接从像素位移换算步长 | 利用身高先验与人体结构先验完成自适应尺度估计，在行走过程中做尺度自校准，把像素轨迹映射到物理尺度 | 4.3 节<br>创新点二 |
| 缺口③<br>快照不等于过程 | 单次评估的结果受当日状态、情绪、疲劳影响，而跌倒风险是缓慢演化的过程；同时单一参数判别力有限 | 以步态变异性（步时、摆动时间的变异系数）为核心特征，做多参数融合与时间序列建模，输出连续趋势而非单次评分，并提供可解释性 | 4.4 节<br>创新点三 |
| 缺口④<br>算力与合规 | 端侧算力有限，需要模型压缩与量化；同时视频上云违反隐私合规要求、依赖网络且带宽成本高 | RKNN 量化部署与算子优化；架构上保证视频帧在设备内完成特征提取后即丢弃，上行仅结构化指标；断网可用 | 4.5 节<br>创新点四 |


### 4.2 核心构造一：面向步态量化的姿态估计改进

本节回应缺口①。核心判断是：**姿态估计模型有很多，但适合“步态测量”的关键点协议几乎没有——这是一个被普遍忽略的错配问题。**


#### 4.2.1 现有做法的三个失效点

- **失效点一：关键点协议不匹配。**主流姿态估计模型采用通用人体关键点协议，关注的是关节位置的整体平均精度。但步态测量真正依赖的是踝、足跟、足尖、骨盆这几组关键点在行走过程中的**相对位移连续性**——而通用协议中，足部关键点往往只标注到踝关节，足跟与足尖要么缺失、要么作为附属点精度不足。当足尖关键点缺失时，“足廓清”（摆动腿足部离地高度）与“足触地时刻”都只能靠踝点近似推断，直接导致步态周期分割与双支撑相计算出现系统性偏差。

- **失效点二：优化目标与误差来源错配。**通用模型以热图（heatmap）方式回归关键点坐标，其误差分布符合关节定位的平均精度评价，但在**低分辨率、远距离、小目标**条件下，热图分辨率带来的量化误差会被放大。而本项目的工作距离是 3–5 米，人体在下肢区域只占少量像素，此时热图量化误差对踝足定位的影响最为显著——而步长对踝足定位误差极其敏感，几厘米的定位误差就足以改变步长变异性的结论。

- **失效点三：逐帧独立估计导致时序抖动。**步态是周期性运动，而逐帧独立的关键点估计会产生高频抖动（jitter）。抖动在单帧指标（如某一帧的姿态）上不明显，但在**变异系数**这类对波动敏感的统计量上是致命的：算法自身的抖动会被误认为老人的步态变异，直接污染本项目最核心的特征。


#### 4.2.2 本项目的改进方案

针对上述三个失效点，本项目做了三项改进。这三项改进共同的特点是：**它们都不是为了刷高通用基准分数，而是为了服务于步态测量这个具体任务。**这一点必须在答辩中讲清楚，因为它解释了“为什么不能直接用一个现成的姿态模型”。

| 改进项 | 具体做法 | 解决哪个失效点 | 如何验证 |
|---|---|---|---|
| 扩展下肢关键点协议 | 在通用关键点基础上，增加足尖、足跟、骨盆（左右髋中点）等步态必需点；重新标注一部分数据以支持新协议；对新增点的标注一致性做专项校验 | 失效点一：协议不匹配 | 标注一致性统计（多人重复标注的偏差）；足触地事件检测的准确率 |
| 改进关键点坐标回归方式 | 把热图式坐标回归改为坐标分类式回归，在低分辨率条件下降低量化误差；配合轻量注意力模块提升远距离小目标的响应强度 | 失效点二：量化误差放大 | 踝、足关键点的像素级误差对比（改进前后、不同距离下的误差曲线） |
| 时序跟踪与轨迹平滑 | 在关键点之上引入多目标跟踪，保持身份连续性；对足端轨迹做物理约束下的平滑（结合步态周期先验，抑制高频抖动） | 失效点三：时序抖动污染变异性 | 在静止站立与匀速行走两种条件下，测量“算法自身造成的变异”指标，目标是显著低于真实步态变异 |
| 轻量化以适配边缘部署 | 在骨干网络中引入轻量化设计，在精度损失可控的前提下压缩参数量与计算量；配合量化感知训练，为 INT8 部署做准备 | 缺口④：端侧算力约束 | RK3576 上的实测帧率、内存占用与精度损失幅度 |

### 4.3 核心构造二：单目弱标定的步态参数提取

本节回应缺口②，是本项目技术上最具挑战、也最有说服力的部分。要讲清它，必须先讲清一个容易被忽略的常识：**相机拍到的是角度和像素，不是距离和长度。**


#### 4.3.1 为什么单目测步长是一个真问题

人眼可以判断“这个人走得很慢”，但很难判断“他的步长是 58 厘米还是63 厘米”。相机同样如此。在单目成像中，同一个 60 厘米的步长，在 2 米处和被 5 米处投影到图像上的像素长度相差数倍；更麻烦的是，老人行走方向与相机光轴不平行时，透视效应会让同一物理步长在不同帧呈现不同的投影长度。

这就是单目视觉的**尺度不确定性**：仅凭一张图像，无法同时确定物体的真实尺寸和它与相机的距离。临床方案之所以用三维动作捕捉或多相机标定，就是为了绕开这个问题——代价是数十万元的设备和专门的场地。

因此本项目的关键技术问题可以精确表述为：**在只有一只普通固定摄像头、没有标定板、没有深度传感器、且不能要求老人配合走固定路线的条件下，如何获得物理尺度上的步态参数？**


#### 4.3.2 本项目的方法：三类先验的联合约束

本项目的思路不是“消除”尺度不确定性（那需要额外硬件），而是用三类先验把它**约束到可用精度**。这三类先验都不需要老人配合，也不需要专业标定：

- **先验一：身高先验。**在建立档案时一次性录入老人身高（家属或护理员提供即可，无需测量设备）。人体各部位长度与身高之间存在稳定的比例关系（这本身就是运动科学中的经典结论），因此身高可以作为尺度标定的锚点，把像素长度换算为物理长度。

- **先验二：人体结构先验。**同一老人的骨骼节段长度在其行走过程中是恒定的。这意味着如果某一帧的尺度估计偏大，会导致推算出的肢体长度超出合理范围——由此可以构造一致性约束，用整个行走序列反解出最合理的尺度参数。**这个约束的强大之处在于：它把一个单帧的欠定问题，变成了一个序列上的超定问题。**

- **先验三：运动学先验。**步态是有规律的周期运动：步频与步长之间、步速与步频之间都存在生理上的合理区间与相关性。当尺度估计出现严重偏差时，推算出的运动学参数会超出合理范围，据此可以进一步校正。

三类先验联合起来，把尺度估计从“无法确定”变成“在合理区间内可确定”。这里必须诚实地说明：这个方法给出的是**统计意义上可用的估计**，而不是标定设备级别的绝对精度。因此本项目的验证目标不是“与金标准完全一致”，而是“与金标准达到足以支撑风险分层的一致性”——这是符合产品定位的、诚实的精度目标。


#### 4.3.3 步态参数提取流程与参数清单

完成尺度标定后，后续的步态参数提取流程如下：

```
① 关键点序列（含足尖、足跟、骨盆）
        ↓
② 足触地/离地事件检测  →  划分步态周期
        ↓
③ 尺度标定（身高 + 结构 + 运动学三类先验联合约束）
        ↓
④ 逐周期参数计算  →  跨周期统计量（含变异系数）
        ↓
⑤ 质量评估（有效步数、遮挡比例、光照条件）
        ↓
⑥ 输出参数集 → 输入风险模型
```

| 参数 | 定义 | 为什么重要 | 单目难度 |
|---|---|---|---|
| 步速 | 行走距离除以时间 | 最强的单一预测因子之一，也是家属最容易理解的指标 | 中 |
| 步频 | 单位时间步数 | 与步速共同刻画行走节律；临床上常与步速联合判读 | 低 |
| 步长 / 步幅 | 相邻两次同侧/异侧足触地之间的位移 | 缩短与风险升高相关；是尺度标定精度的直接体现 | 高 |
| 步幅时间变异系数（CV） | 步幅时间标准差除以均值 | 本项目核心特征之一。多项研究显示变异系数比均值更能可靠预测跌倒风险 | 高（对抖动敏感） |
| 摆动时间变异系数 | 摆动相时间的变异系数 | 与跌倒风险高度相关，是最具预测力的参数之一 | 高 |
| 双支撑相占比 | 两足同时触地的时间占步态周期比例 | 反映平衡功能下降，延长与跌倒风险正相关 | 中高 |
| 步宽 | 两足横向间距 | 步宽增加常被视为稳定性的代偿策略，与风险相关 | 高 |
| 对称性 | 左右两侧步态参数的差异程度 | 不对称性与跌倒风险相关，也提示单侧功能问题 | 中高 |
| 转身时间 | 从开始转身到完成转身的耗时 | 对应 TUG 中的转身环节，平衡能力的重要指标 | 中 |


#### 4.3.4 与临床金标准的一致性验证设计

这是本项目的成败关键，也是答辩中最容易被追问的部分。验证设计的核心是：**在同一批老人、同一天、同一时段，同时用本系统和临床金标准各测一次，然后做一致性分析。**

| 验证环节 | 设计要点 | 输出指标 | 诚实要求 |
|---|---|---|---|
| 样本设计 | 招募一定数量的老年人（含不同风险层级），覆盖不同身高、不同体型、不同步态特征 | 样本量、招募渠道、入组与排除标准 | 必须写明样本量与人群特征，不得用“若干”“大量”等模糊表述 |
| 金标准对照 | 以临床步态分析设备（三维动作捕捉或电子步道）或规范的 TUG 测试作为对照，同日完成 | 两种方法测得的参数配对数据 | 必须写明金标准的设备型号、测试流程与测试人员资质 |
| 一致性分析 | 对连续型参数做一致性与相关性分析；对分类型结果做交叉表分析 | 一致性相关系数（ICC）、Bland-Altman 偏倚与一致性界限、Spearman 秩相关、风险分层的交叉表与 Kappa 值 | ★ 如实报告结果，包括不一致的部分。如果某类参数一致性差，就写明“该类参数暂不参与风险判定” |
| 重复性验证 | 同一老人重复测量，评估系统自身的稳定性 | 重复测量的变异范围 | 必须区分“系统自身变异”与“老人真实变异”，这是本项目最需要证明的技术能力 |

关于“重复性验证”这一行，需要特别强调：本项目最核心的技术主张是“能测出步态变异性”，而变异性恰恰是最容易被算法自身抖动污染的量。因此必须专门设计实验证明“我们测到的变异主要来自老人，而不是来自算法”。这个实验的设计与结果，是整个技术方案中最有说服力的一环，建议作为答辩 PPT 的核心页之一。


### 4.4 核心构造三：以步态变异性为核心的风险分层模型

本节回应缺口③。核心判断有两句话：**第一，均值不如波动；第二，快照不如过程。**


#### 4.4.1 为什么选步态变异性作为核心特征

在步态与跌倒风险的研究中，有一个反复出现的结论：步态参数的**变异程度**往往比其**平均水平**更能区分跌倒者与非跌倒者。这个结论的直观解释是：稳定的步态需要神经系统、肌肉骨骼系统与感觉系统的协同控制；当这种协同能力下降时，走路会变得“忽快忽慢、忽长忽短”，表现为变异系数的升高——**变异系数上升反映的可能是控制能力的退化，而平均值的下降可能只是走得慢一点，两者的临床含义并不相同。**

这个判断直接决定了本项目的技术选择：如果只做单次测量，很难稳定地估计变异系数（单次测量中变异系数本身就不稳定，需要足够的步数）；而连续监测恰恰提供了估计变异系数的理想条件。**换句话说，产品的形态（连续、无感）与算法的需求（多样本、稳定估计变异系数）是天然匹配的——这不是巧合，而是本项目产品设计与技术设计相互成就的地方。**


#### 4.4.2 模型结构

风险模型采用“特征层 + 时序层 + 输出层”的结构，刻意保持可解释性优先、模型复杂度次之的原则：

| 层次 | 内容 | 设计考虑 |
|---|---|---|
| 特征层 | 单次采集参数（步速、步频、步长、双支撑相等）+ 变性特征（各参数的变异系数）+ 个体基线偏离度（与本人历史基线相比的偏离）+ 质量特征（有效步数、遮挡比例、光照条件） | 把“与本人基线比”作为显式特征，而不是让模型隐式学习——因为老年人个体差异极大，绝对阈值式的判断天然不适用于个体化风险评估 |
| 时序层 | 以日为单位聚合的特征序列，建模趋势、波动与突变 | 优先选择可解释的时序模型；在数据量不足时不要强行上深度时序模型，这是学生团队最容易犯的错误——数据不够时，复杂模型只会更难解释、更易过拟合 |
| 输出层 | （1）风险等级：低 / 中 / 高<br>（2）连续风险评分<br>（3）主要贡献因素排序<br>（4）置信度与数据质量声明 | 四类输出缺一不可。只有等级没有贡献因素，护理人员不知道该怎么办；只有评分没有置信度，无法回答“数据不可靠时系统怎么处理” |


#### 4.4.3 可解释性与临床对齐

本项目在可解释性上有两个明确要求，它们都来自“产品要给护理人员用”这个现实约束：

- **要求一：每个风险判定都要能说清“主要因为什么”。**输出按贡献度排序的风险因素，例如“本次风险升高主要来自步速下降与摆动时间变异系数升高”。这不仅让护理人员知道该做什么，也让临床人员能判断系统结论是否合理。

- **要求二：模型的输出要能与临床语言对齐。**把风险评分与临床量表、TUG 测试结果做对照，给出“本系统的中风险大致对应临床上什么状态”的映射关系。没有这层映射，系统就是一个“黑箱打分器”，无法被临床人员接受。

| 评测指标 | 含义 | 目标准则 | 状态 |
|---|---|---|---|
| AUC（ROC 曲线下面积） | 区分跌倒与非跌倒老人的能力 | 文献级多参数模型 AUC 约 0.85–0.98；本项目目标 AUC ≥ 0.85 | 【目标值·待实测】 |
| 与 TUG 的相关性 | 与临床常用指标的关联强度 | 期望达到中等以上相关，用于建立与临床语言的映射 | 【待实测】 |
| 风险分层的准确性与一致性 | 三档分层与临床评估的一致程度 | 报告交叉表与 Kappa 值，如实呈现 | 【待实测】 |
| 稳定性（重复测量一致性） | 同一状态下重复测量结果的一致程度 | ★ 本项目的关键技术指标，直接决定“能否测出真实变异” | 【待实测】 |
| 早期预警能力 | 在跌倒事件发生前是否已出现风险上升 | 通过回访发生过跌倒的案例做回顾性验证；样本量不足时如实说明为探索性结果 | 【待实测·样本受限】 |


### 4.5 核心构造四：RK3576 端侧部署与隐私安全架构

本节回应缺口④。这一节看起来是“工程实现”，但实际上是本项目商业模式成立的前提——**如果视频必须上云，这个产品在养老机构和家庭的卧室门口就永远装不下去。**因此隐私安全架构不是技术细节，而是产品定义的一部分。


#### 4.5.1 硬件平台：RK3576

| 规格项 | 参数 | 对本项目的意义 |

| 接口 | USB 3.0、MIPI CSI、PCIe 2.1、以太网、Wi-Fi | USB 摄像头 UVC 免驱接入；MIPI CSI 作为画质升级路径 |
| 工具链 | RKNN-Toolkit2 | 模型转换与量化部署的成熟路径，降低端侧落地的工程难度 |
| 工艺与定位 | 8nm 制程，面向 AIoT 与工业市场的国产化应用处理器 | 国产芯片供应稳定；功耗与成本适合长期部署在养老场景 |


#### 4.5.2 端侧部署的技术路径

```
训练阶段（PC / 服务器）
    PyTorch 训练改进姿态估计模型
        ↓
    ONNX 导出
        ↓
    RKNN-Toolkit2 转换 + 量化（含量化感知训练后的权重）
        ↓
部署阶段（RK3576 边缘盒）
    模型加载 → NPU 推理（关键点）
        ↓
    CPU 侧：多目标跟踪 → 步态周期分割 → 参数计算
        ↓
    CPU 侧：风险模型推理 → 结构化指标
        ↓
本地：告警触发 → 网络可用时上传结构化指标（KB/天级）
        网络不可用时本地缓存，联网后续传
```


#### 4.5.3 隐私安全架构：三条不可逾越的红线

本项目的隐私设计不是一堆原则表述，而是三条可以直接验证的技术约束。建议在 PPT 与商业计划书中原文呈现，因为它清晰、可核查、且直接回应了养老场景最敏感的顾虑。

| 红线 | 技术实现 | 如何验证 |
|---|---|---|
| 红线一：视频帧不出设备 | 摄像头采集的视频帧在设备内存中完成关键点提取后立即丢弃，不做落盘、不上传、不留存。设备内不提供视频回放功能（这是刻意的功能缺失） | 抓包验证：整机运行期间对外网络流量中不含视频数据；检查设备存储无视频文件残留。★ 答辩现场可演示抓包 |
| 红线二：上行只有结构化指标 | 上传内容仅包含数值型参数、风险评分、设备状态与时间戳；单个老人单日的上行数据量在 KB 级 | 统计上行数据量与内容结构；提供数据字段清单供第三方核查。★ 与视频上云方案做数据量对比 |
| 红线三：断网可用、可离线运行 | 核心推理全部在端侧完成，不依赖云端服务；网络中断时本地缓存数据与本地告警不中断 | 断网演示：拔掉网线 / 关闭 Wi-Fi 后系统仍能完成采集、计算与告警。★ 答辩现场可演示 |

此外还有两项配套设计，属于合规层面的必要工作：

- **最小必要与知情同意**：系统仅采集步态相关的必要数据，不采集身份生物特征、不做人脸识别；部署前向老人与家属说明采集范围、数据用途与存储期限，并取得书面同意；提供随时退出机制。

- **数据权限分级**：机构管理员可见本机构数据，家属仅可见其关联老人的数据，系统不向第三方提供个体级数据；所有查询与导出操作留痕。

### 4.7 技术栈与选型说明

| 环节 | 选型 | 选择理由 |
|---|---|---|
| 姿态估计 | YOLO 系列单阶段姿态估计模型（改进后） | 单阶段模型在边缘设备上延迟低、工具链成熟；本项目在其基础上做关键点协议与回归方式的改进 |
| 多目标跟踪 | 主流跟踪算法（如基于检测的跟踪框架） | 解决多人场景身份关联与轨迹连续性；成熟方案优先，不重复造轮子 |
| 时序建模 | 可解释的时序模型优先，数据量充足后再考虑深度时序模型 | 学生团队最常见的失误是在数据不足时上复杂模型，导致过拟合且无法解释 |
| 端侧推理 | RKNN-Toolkit2 + INT8 量化（配合量化感知训练） | 官方工具链成熟；量化是端侧实时性的必要条件 |
| 后端 | 常规 Web 后端 + 关系型数据库 + 时序数据存储 | 数据量级不大（KB/天/人），不需要复杂的大数据架构；保持运维简单，这是学生团队能维护的前提 |
| 前端 | Web 管理后台 + 微信小程序 | 机构用 Web（大屏与电脑），家属用小程序（手机），符合各自的使用习惯 |
| 数据集与标注 | 公开人体姿态数据集做预训练；自建老年人行走数据集做微调与验证 | 公开数据解决冷启动；自建数据是精度的关键，也是本项目的核心资产之一 |


### 4.8 数据集、标注与评测规范

数据是本项目最需要提前规划、也最容易在答辩中被追问的部分。本项目的处理原则是：**公开数据解决冷启动，自建数据形成壁垒，标注规范保证可复现。**

| 数据类别 | 用途 | 获取方式 | 注意事项 |
|---|---|---|---|
| 公开姿态数据集 | 预训练姿态估计模型，验证改进模块的有效性 | 使用公开数据集，严格遵守其许可条款 | 必须记录数据集版本、许可类型与使用范围；★ 不得声称自建 |
| 自建老年人行走视频 | 微调模型、验证步态参数精度、构建步态数据集 | 在合作机构内拍摄，使用本项目硬件；签署知情同意书；视频仅用于算法训练，训练完成后按约定销毁或脱敏保存 | ★ 必须取得书面同意；★ 必须通过伦理审查（如学校或合作机构有要求）；★ 建立数据使用台账 |
| 临床对照数据 | 与金标准做一致性验证 | 与合作医院或康复科联合采集，由专业人员操作金标准设备 | ★ 必须有合作单位的正式协议；★ 数据归属与发表权利需事先约定 |
| 合成与增强数据 | 补充遮挡、光照、距离等困难场景 | 在真实数据基础上做受控增强，或使用仿真人体模型生成 | 注意：增强数据不能替代真实数据做最终验证；必须说明增强策略与比例 |
| 标注规范 | 保证标注一致性与可复现 | 编写标注手册，规定关键点定义、遮挡情况处理、边界情况判定规则 | ☆ 多人重复标注计算一致性；标注手册应作为材料附件，体现工程规范性 |


### 4.9 技术边界与诚实声明

本节的内容建议直接翻译成答辩话术。主动、准确地说明技术边界，比含糊其辞地宣称“什么都行”更能赢得评委的信任。以下五条是必须主动说明的：

- **关于精度**：本项目给出的是统计意义上可用的步态估计，不是标定设备级的绝对测量。我们的目标是“与金标准达到足以支撑风险分层的一致性”，而不是“与金标准完全一致”。具体的误差范围以实测数据为准，未测之前不作声称。

- **关于适用场景**：系统适用于光线条件稳定的室内走廊或客厅，需要 3–5 米的直线行走空间。在极度拥挤、剧烈遮挡、光线剧变（如强逆光）的条件下，数据质量会下降，此时系统会标注低置信度并暂不参与风险判定，而不是强行输出结论。

- **关于人群范围**：系统面向能够独立或在辅助下行走的老年人。对于长期卧床或依赖轮椅的老人，本系统不适用——这是产品定位的边界，不是缺陷。此外，使用助行器（如四脚拐、助行架）时的步态参数提取是当前的技术难点，我们会在部分场景下标注为“辅助行走模式”，并谨慎解读其参数。

- **关于临床定位**：本系统输出的是风险提示与趋势，不构成医学诊断，不替代医护人员的专业判断。我们的定位是“把临床上有效的指标变得可日常化、连续化”，把专业判断的输入从“一年一次的快照”变成“每天一条曲线”。

- **关于因果与预测**：我们识别的是统计关联，不是因果关系。风险评分升高不代表“一定会跌倒”，风险评分正常也不代表“一定不会跌倒”。因此本系统的价值在于“帮助机构把护理资源投向更需要的老人”，而不是“给老人一个安全承诺”。在推广中我们不会使用“防止跌倒”这类表述，而使用“识别与提示跌倒风险”——这个措辞的严谨性恰恰是产品可信度的一部分。
